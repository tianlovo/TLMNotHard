# 原版女仆自然跟随观察器

本工具在独立的 Minecraft 1.20.1 参考客户端中注册真实的原版 `EntityMaid`，让完整的 `Brain` 与原生寻路导航随真实世界 tick 自然推进。
本工具专注于采集原版自身在未固定随机源下的轨迹变异，为行为 AI 提供客观的比对基线。

## 背景

固定运行环境为上游 TLM 提交 `8a3ac5e9eacf0c6d63adf8832949f3ce81484fe6`、Forge 47.2.0 与 Java 17。
受测女仆直接使用精确的原版类，不挂载测试子类、不开启 `noAI`，也不手工调用 `Brain` 或 AI 内部方法。
测试主人取自当前 `IntegratedServer` 的 `PlayerList` 与真实客户端连接；采样期间由受保护的旁观模式临时切为创造模式，采样结束后立即恢复。
主人的移动轨迹由控制脚本经真实服务端连接执行 `teleport` 注入，不代表人工键盘输入。

由于原版开局赠送的魂符可能占据当前主手，准备阶段会先保存玩家原有的 `selected slot`，切换到现有的空快捷栏槽位并发送真实的 `carried-slot` 同步数据包。
准备过程绝不删除、搬移或回填任何背包物品；若快捷栏无空槽或副手非空，工具会直接拒绝启动采样。
采样期间每一帧都会严格校验主副手为空，结束时切回原槽位，并逐格核对 9 格快捷栏与副手的 `ItemStack.matches` 及前后 NBT 摘要。
`status` 命令在真实的客户端主线程读取 `clientSelectedSlot` 与双手物品，不会拿服务端发包记录冒充客户端已完成同步确认。

原版 `ALL` 日程在日间实际激活 `WORK` 活动。
`TaskIdle` 下的工作子任务、`core` 活动、随机漫步、传感器及其他原版活动全部保持开启，不会为了凑出一致轨迹而删减任务或逐 tick 重置随机数生成器。
当前启用合同为 `FOLLOW_NATURAL_WATER_O_V1`，包含封闭水道与水下一格高矮通道两个场景，每个场景各新建三次独立女仆，合计采集 1200 个实体观测帧。
早期平坦地形合同覆盖直行后停步、直角转向与跨传送距离边界三个场景，归档为 `flat-contract-v1.json`，其历史样本继续使用配对的冻结工具复核。
由于世界 RNG、实体 RNG 与传感器初始相位均不人工固定，每个场景三次重复观测不构成统计显著性证明。

## 安装

复用既有的独立原版源码 checkout、动画参考基础初始化脚本、已审批工具链锁及仓库外运行目录。
将环境变量 `TLMNH_FOLLOW_NATURAL_PROBE` 指向本目录，同时保留 `TLMNH_REFERENCE_PROBE`、`TLMNH_REFERENCE_HOME`、Git 与 Java 17 配置。
构建时仅需传入本目录的 `reference.init.gradle`；该脚本内部会自动引入原版基础 init，请勿重复叠加其他参考工具的 init 脚本。
身份准备任务为 `prepareFollowNaturalReferenceIdentity` 与 `followNaturalDefinitionAgentJar`，生成的构建身份清单写入外部 `HOME` 的 `identity/follow-natural-build.json`。

该初始化脚本会关闭旧版 `reference`、`geometry`、`follow`、`move` 采样开关，启用独立的 `natural` 开关与专属资源目录。
只读首次类定义观察器复用 `geometry` 工具的 agent 实现，但选定类集合与构建身份清单彼此独立，原有基础身份锁仍单独校验；选定类的资源摘要与首次定义摘要分列记录，不外推为整套 classpath 的完整性保证。

## 使用

```text
python tools/follow-natural-reference/control.py status
python tools/follow-natural-reference/control.py lab_open
python tools/follow-natural-reference/control.py capture_natural
python tools/follow-natural-reference/control.py cancel
python tools/follow-natural-reference/compare.py <capture.json.gz> --build-identity <follow-natural-build.json>
python tools/follow-natural-reference/test_compare.py
```

首次尚无专用实验存档时使用 `lab_create` 创建，已有同名存档时拒绝覆盖。
控制根目录位于外部 `HOME` 的 `client/tlmnh-follow-natural-reference`，就绪标记为 `TLMNH_FOLLOW_NATURAL_REFERENCE_READY`，采样摘要标记为 `TLMNH_FOLLOW_NATURAL_REFERENCE_CAPTURE`。
原始观测 JSON 以 `gzip` 压缩保存，控制响应仅返回相对路径、哈希摘要与字节长度。
若单次轮询等待超时，请保持同一运行进程与当前请求不变，先通过 `status` 查看进度，切勿自动重启客户端或并发发起重采。

采样开始前，主人会先在 `65×65` 的专用石头/空气实验平台及封闭水域内预热真实的区块加载票据；女仆在某个 `LevelTick` 的 `END` 阶段真实加入世界，自下一个 `START` 阶段起记录 `frame0`，完整保留出生与首帧之间的自然状态，不人工回拨已发生的 tick 或坐标。
每个 tick 的 `START` 阶段记录计划轨迹与实际调用后的主人输入，`END` 阶段记录主人与女仆的实际状态、当帧 `LivingTick` 次数、`Brain` 记忆、寻路节点、当前活动、控制器状态与实体属性。
移动速度的基础值、最终属性值、`AttributeModifier` 与导航 `speedModifier` 分开采集，不能预先假定 GTNH 2.9.0 的 `0.3` 与原版数值语义一致。

`NEAREST_VISIBLE_LIVING_ENTITIES` 记忆仅导出底层候选实体列表，不主动触发其可见性谓词求值，避免篡改惰性缓存；出现在候选列表中不等于已通过可见性判定。
在同一个 tick 内启动并立即结束的瞬时行为无法仅凭 `END` 快照反推调用次数；单帧较大位移也不直接等同于触发了 `teleport` 方法调用；若遇到未登记的记忆值类型，探针会保留失败现场而不编造默认值。

`compare.py` 先依次校验实体真实注册、在线主人连接、轨迹输入生效、自然 tick 递增、构建身份与场景清理，随后输出坐标与时钟归一化后的逐帧首个分歧及描述性统计。A/A 多次采样之间的不一致如实记作自然变异；输出聚焦于首次偏离的时间步、欧氏距离与朝向差分，提供客观的物理分布参考。归一化仅对齐已知参与者 ID、场景原点与相对帧号，完整保留真实的速度、位移与属性状态。

## 开发状态

当前水域合同已完成全部 6 轮、1200 帧原版采样，构建身份、轨迹输入、自然 tick、水域地形与玩家状态恢复检查全部通过。
封闭水道包含 153 个水源方块与 176 个玻璃方块，水下矮通道包含 129 个水源方块与 212 个玻璃方块；每轮前后均校验实际方块摘要，清理时先排空水源再拆除玻璃外壁，若检测到未知方块变动则拒绝覆盖现场。
探针直接读取当前路径节点的类型与代价而不额外发起寻路搜索；实测中水道场景出现了 `WATER_BORDER` 节点，矮通道中也观察到较大的单帧位移，不能单凭位移幅度断言发生了传送调用或穿墙。
多次重复采样的轨迹存在自然变异；由于随机源未固定，该数据集不用于判定严格逐帧等价、完整 `F` 模式验收或统计显著性收益。
Python 侧的解析与归一化单测仅验证脚本自身逻辑，不能充当原版 AI 的替代真值源。首次启用新合同时，须完整归档构建清单、身份记录、原始采样、A/A 变异报告与失败日志，再决定后续对照方案。

无论采样正常结束、人工取消、主人断线还是服务端停机，清理流程都会尝试移除测试女仆、按逆序还原实验方块，并恢复世界日时、天气、游戏规则与主人原始状态。
原生 `PlayerList.remove` 会在写入玩家存档前派发退出事件，探针会在该事件回调内优先还原主人模式与槽位。
只要任一清理步骤未确认完成，响应中的 `complete` 即保持 `false`；客户端游戏模式回显与 `player.dat` 磁盘落盘状态仍单独标注为未验证。观测异常与各阶段清理异常分开记录，完整堆栈保存在外部私有日志中；若观测中途失败但现场清理全部成功，允许出现 `cleanupComplete=true` 且 `complete=false`。进程强杀、断电或跨文件系统的多文件原子回滚不在本工具保证范围内。

## 历史平坦合同的移植侧观察

Indev117 在独立的 Horizon-QA 测试模组中提供了 `NaturalFollowPortTests`，按历史平坦合同的三条主人轨迹各新建三次女仆进行采集。
移植侧观察器同样在真实的 `START/END` 阶段注入轨迹并记录状态，不重置世界与实体 RNG，并将原版的真实联网玩家主人与移植侧的标准 `FakePlayer` 明确区分标注。
产出的 `follow-natural-port.json.gz` 须与同轮 HQA 状态 JSON、JUnit XML 及进程退出码联合核验，数据采集完成不等同于跟随能力验收通过。

`compare_port.py` 接收原版 `O` 采样、原版构建身份清单、当次原版冻结工具目录、移植端采样、HQA 报告及预期玩法 JAR SHA。
当仓库内现行工具脚本继续演进后，复核历史数据时须传入配对的冻结工具目录校验全部输入 SHA，既不放宽校验断言，也不用新版脚本的哈希差异否定既有历史样本。
比较器核验原版身份/输入/清理以及移植端 9 只独立实体、1800 帧、同一主人身份、自然年龄递增、输入轨迹、移动属性、实体移除与进程退出码后，输出主仆距离曲线及组内、组间 RMS 描述指标。
受限于每个场景仅三次未固定随机重复、主人实体实现不同以及跨版本物理差异，该结果不用于判定严格等价或统计显著性收益；完整 `F/N` 验收、复杂地形恢复、运算成本与远程预瞄收益均须另行独立验证。

## 当前水域的移植侧观察

开发单元 Indev123 通过独立的 `NaturalWaterPortTests` 在生产候选 Indev121 上完成了同一水域合同的 6 轮、1200 帧采集；观测记录、场地还原、真实 HQA `1320 tick` 运行及 JSON/XML/退出码 `0` 全部核对一致。
`compare_port.py` 同时兼容历史平坦合同与现行水域合同：原版侧必须传入配对的冻结工具目录，水域模式还会额外比对完全一致的合同 SHA、场景定义与前后方块计数。
在封闭水道场景中，原版与移植侧首次进入主人 `2.5` 格范围内的时刻均为第 `52` 帧，且实际寻路节点均包含 `WATER_BORDER`；但后半程游动轨迹与身体姿态存在差异，不据此下达严格等价、统计收益或远程预瞄结论。
由于移植侧仅在 `END` 阶段采样、缺少首帧前的出生快照，首帧位移固定标记为未观测；原版侧具备 `before/after` 记录，如实保留真实的首帧较大位移，但不单凭位移数值推定调用了传送方法。
移植侧标准 `FakePlayer` 与原版真实联网主人的差异以及跨版本水下物理差异均在报告中明确列出，下一步需推进完整保留活动的忠实模式 `F` 准入核查，不能用这批观测替代全量验收。

## 实际 F 身份与 v2 捕获

`v2` 采样格式改为每轮从实体受保护策略入口真实选择模式，记录初始及逐帧的实际 `profile`、运行上下文 UUID、`epoch` 与实例绑定稳定性，并一并保存玩法候选与观察器 JAR 的整包 SHA 及关键打包类资源摘要。
运行 `compare_port.py --expected-port-profile faithful_tlm --candidate-jar <玩法包> --pilot-jar <实际观察器包>` 时，强制要求 `v2` 格式、真实的 `F` 模式运行证据及类资源哈希匹配；旧版 `v1` 样本仍可按默认组件模式复算，但无法建立完整 `F` 身份。两份采样合同的原始字节 SHA 与原版配对冻结文件完全一致，打包类资源核验不代表已证明运行时类加载变换后的字节定义。

开发单元 Indev128 在平坦地形（9 轮 1800 帧）与封闭水域（6 轮 1200 帧）上均通过了身份、输入、场地还原与移动属性核验，样本分组标记为 `F_development`。
逐帧篡改 `profile`、篡改打包类资源摘要以及拿旧组件样本冒充完整 `F` 三种真实负例均被比较器拒绝，历史 `v1` 描述性指标复算结果保持不变。本批仅输出描述性轨迹差异，未固定随机源、主人实体实现及跨版本物理差异等限制依然存在，完整 `F/N` 验收与统计准入继续保持 `false`。

开发单元 Indev144 新增增强核心组件对照分组：观察器通过 `-Dtlmnh.qaNaturalProfile=enhanced_core_component` 从真实增强策略工厂创建实例，比较器通过 `--expected-port-profile enhanced_core_component` 绑定当次玩法与观察器 JAR。
增强组件分组会记录并核验四个生产类资源、逐帧增强 `Brain`/上下文/决策计数及真实的 `NATIVE_MOTION_COMPENSATION` 弹道配置（不在无弓跟随场景中将其篡改为原版弹道标签）；原有 `F` 分组的三类核验格式保持不变，类资源集合与实际 JAR 条目摘要继续要求严格相等。
复用 Indev143 玩法候选采集的平坦 9 轮 1800 帧与水域 6 轮 1200 帧均通过合同、地形、清理、移动属性及策略身份校验；零增强决策、篡改增强类资源摘要以及在帧内伪造 `F` 标签三类负例全部被拒绝，历史 `F` 描述性指标复算一致。
平坦场景首次进入 `2.5` 格均为第 `21` 帧，封闭水道为 `O=52 / N=48` 帧，水下矮通道 `N` 为第 `120` 帧；后半程闲逛半径与掉队重追响应仍存在差异，既不把单一场景更快当作整体优势，也不把大跨度位移当作传送调用证明。本批仍属有界开发期观测，完整增强模式 `N`、严格等价、统计显著性收益与运行开销评估均尚未准入。

## 完整增强模式的自然身份采集
