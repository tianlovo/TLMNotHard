# 原版 TLM 1.20.1 动画对照实验

这是测试工具的实验入口，用于运行Minecraft1.20.1与该版本的上游原版TLM
GTNH模组仍以Minecraft1.7.10为目标，此目录的Java17探针不加入其源码集或分发JAR

小样本已在实际原版客户端采到两条路径的数据：汉服酒狐115根骨骼、Bedrock酒狐126根骨骼，各30帧，均无模型回退
实际加载清单仅有Minecraft、Forge与上游TLM，采集阶段上游源码保持不变
受控原版A/A已通过：两种模型各重建三次、每次30步，四组逐字段对照均无差异
实际执行路径中的位移、时钟和动作选择故障也已自动检出
两个空手待机样本已完成CPU回放：修正启动和循环时序后均逐值一致；通用输入与GPU检查仍未完成

## 受控动作转换实测

新增`idle_walk_idle`小实验：两模型各独立重建三次、每次72步，24步待机、24步走动、24步待机
实际原版A/A四组比较差异为0，汉服27根、Bedrock6根骨骼变化
汉服主控制器第23步为idle、第24/47步为walk、第48/71步为idle，由实际条件选择，没有直接指定正确片段
每步实际输入钩子和Gecko原版更新返回值均经过严格校验

移植CPU重放两模型逐值一致，实际Head位移故障和缺少groundSpeed的Java拒绝也通过
新报告分别为`aa-idle-walk-idle-experiment.json`与`ab-idle-walk-idle-experiment.json`，没有覆盖旧待机证据
原版参考客户端正常保存退出，这轮不是只比较手工构造的输出文件

这仍是原地运动学动画夹具：步态、速度与previous position按同一合同变化，当前位置没有实际推进
它不证明真实移动、导航、实体快照绑定、非零头转向、随机、装备或GPU成像，`approved_for_bulk`仍为false

## 非零头转向与真实绑定实测

`head_turn`复用两模型，四段共72步：零角、yaw30/pitch15、yaw-45/pitch-20、回到零角，单位为度
实际原版各独立重建三次，四组A/A比较差异0；移植版A/B也逐值一致，Head实际位移故障和缺输入拒绝通过
Gecko分别采核心、头部和最终姿态，18至53步实际头部阶段改变；Bedrock只比较真实可观测的最终姿态
回放器另检查可选核心观察点没有改变同输入播放器的输出，不要求不同动画阶段彼此相等

CPU重放从采集DTO构造输入，仍会绕过真实RC2取帧代码，因此另在实际RC2客户端做了六个输入绑定用例
Gecko正负角、实际恢复旧符号的故障、修复路径恢复，以及Bedrock正负角均按实际读值判定
结果中故障用例bindingMatched=false、恢复用例为true，每次都恢复8个实体角字段，未通过编辑保存后的JSON制造失败
该探针从实际实体字段经过原生RendererLivingEntity取得参数，再读取播放器实际消费的query
Gecko相对yaw经wrap/clamp后与pitch取负，Bedrock继续使用正号；此次比较推动补齐了真实路径的符号转换

六例通过只覆盖这两模型与指定头部角度，不证明速度、手槽、全部实体快照、动作或最终像素
同轮完整候选实验另有命名开窗夹具失败，保留整轮失败；独立的头部六例不被写成整候选通过
这轮确认了分层检查的必要性：冻结输入回归负责计算，真实客户端绑定探针负责输入链，GPU检查负责成像盲区

## 长期维护的决策

原版客户端用于建立独立参照，日常以冻结输入的CPU重放为主
不把两版同时播放的录像帧号、截图差异数量或跨版本逐像素相等作为移植是否正确的判据
不同时间轴、光照和渲染后端会干扰归因；两边一样也只能说明被覆盖场景未发现新增差异

目前只确认两个模型的待机、受控动作转换、头转向回放和指定角度真实输入绑定可用，尚未批准批量模型验收
两模型各三次独立重建、每次30步的原版A/A重复一致，骨骼随时间变化
比较曾定位到移植版启动和循环计时差异，修正后才一致，实际执行路径的故障也能检出
这证明有用性，不证明所有动作、随机、物理或画面已经可比
真实RC2头部绑定已有独立正反例，速度、装备和其他快照绑定仍需补验
DTO字段回显一致不等于所有运行时依赖已正确采集，不能以继续增加DTO样本替代真实输入验证

| 层次 | 主检查 | 当前边界 |
| --- | --- | --- |
| 原版采集 | 资源、输入、更新序列和原版A/A | 两模型的受控待机、原地走动转换和头转向 |
| CPU回放 | 控制器及分层局部姿态，输出首个分歧 | 父级累积矩阵、完整动作和通用随机合同未验证 |
| 实际输入绑定 | 实体、原生render参数和实际消费query，真实错误负例 | 已测指定头部角度，速度、装备等仍待验证 |
| 提交桥 | 真实RC2的顶点参数、UV与纹理绑定，故障注入后恢复 | 预期流共用几何函数，不是独立几何或GPU结果 |
| 实际成像 | 固定RC2环境的截图或离屏图，检查缺件、透明与状态污染 | 自动成像判据尚未证明，不以CPU或提交桥通过替代 |
| 双端玩法 | 实际客户端请求、服务端权威状态与同步 | 单独运行，不由动画回放推导 |

恒定步长的idle→walk→idle和非零头部转向已经通过上述有界实测，仍保持这两个模型，下一项单独引入不均匀步长或随机
动作须由实际输入条件选择，正例不能直接指定正确片段来绕过控制器条件
区分原地构造步行动画输入和实际移动，同时记录limb参数、实体速度与位移查询；不把动画用例当作随行或导航benchmark
新合同先各重建三次验证A/A，再做A/B；通过后才逐项加入头部转向、不均匀步长和随机
物理必须重放相同更新序列，不能只对齐终点时刻；不同步长序列彼此不要求姿态相同
缺字段、未捕获的随机调用或不稳定的原版A/A返回不可判定，不能填零或调宽容差

若某类输入无法稳定重放，则限制其精确比较范围，改用受控片段、不变量和同一RC2环境的图像回归
替代检查也要通过实际故障负例，明确仍未覆盖的部分；不能将不可判定改成通过
跨版本图像用于缺件和严重异常筛查，像素基线只在已记录的相同渲染环境内使用
成像层先验证提交桥的盲区，例如只破坏外层模型矩阵或全局透明度，确认流仍一致时画面检查能报错
这项负例尚未执行；现有trace未记录外层OpenGL矩阵，预期流和实际流又共同使用当前颜色，不能承担这项验证

| 变更 | 默认测试范围 |
| --- | --- |
| 仅文档或IDE配置 | 对应文本、路径或配置检查 |
| 动画计算、控制器、查询或动作绑定 | 受影响的冻结CPU轨迹与故障负例 |
| 几何、UV、材质、装备或渲染接口 | 对应CPU检查及真实RC2渲染场景 |
| 上游、资源、探针或输入协议 | 新版本原版A/A、故障检出和A/B，保留旧基线 |
| 发布候选 | 必需动作、35酒狐逐项、其余内置模型和双端矩阵 |

不为每次push启动两套客户端，也不重复采集未变化的原版参照
每轮记录源码、资源、探针、输入合同、运行环境、实际耗时和证据摘要
参考身份还需自动核对实际HEAD、补丁及加载类摘要，不能只相信探针中写死的上游提交字符串
当前小样本未测出全量耗时或误报率，不能据此承诺固定运行成本
大量原始轨迹、游戏文件与图片留在源码checkout之外，禁止提交本机绝对路径
输入合同稳定后还需保存小型、不可变的必要轨迹及摘要清单，或提供固定且可校验的测试附件
目前原始实测轨迹仍在独立运行目录；换机器的离线回归和干净checkout复现尚未验收，不能把本机实验通过写成便携性完成

参考上游构建还含ForgeGradle区间、librarian动态版本和mixingradle SNAPSHOT，仅固定TLM提交不足以固定工具链
批量接入前须冻结小型样本包及其清单，并记录和校验实际解析的工具JAR、探针、补丁、重放器与比较器摘要
现有请求记录已有实际upstream HEAD、dirty和探针摘要，但未自动聚合为已加载原版类的身份校验；不得只信配置中的提交标签
基线有差异先保留旧版本、定位来源并记录变更理由，不按移植结果自动覆盖样本或扩大容差
当前只有按路径触发的文档CI，没有已经部署的动画CI；GPU矩阵负例、干净checkout离线回归通过前不把全量游戏测试接到每次push

自动工具先分类失败、定位首个差异并缩小用例，由开发代理复现和查看必要的少量差异帧
日常逐模型循环观看不交给用户；玩法取舍、难量化的观感和最终验收仍需要人工判断
增强行为AI另用任务成功率、响应、恢复与运行成本做benchmark，不要求逐tick复制原版决策

此处借鉴[Riot的录制重放与首个分歧定位](https://www.riotgames.com/en/news/determinism-league-legends-fixing-divergences)，
以及[OpenUSD区分普通对比和显示设备测试的流程](https://openusd.org/24.08/api/_page__testing__guidelines.html)
它们提供方法参考，本项目是否可用仍以自己的实际实验为依据

## 选型与限制

计划先验证原版实际轨迹采集、移植版输入重放和分层姿态差分，再补两端实际渲染检查
两个世界同时播放后按录像帧号或截图直接判等价，会混入渲染时刻、随机数、物理步长及坐标系差异

动画回归中冻结数据、比较逐帧关节变换已有实践依据，但还须在本项目做小样本实验
参考：[Mohr-Daurat，SCA 2017](https://doi.org/10.1145/3099564.3106641)

结构化状态日志与首个分歧定位也有长期维护经验可参考
参考：[Riot，Fixing Divergences](https://www.riotgames.com/en/news/determinism-league-legends-fixing-divergences)

## 便携实验脚本

Python工具需要3.12或更高版本、Git和已经启动的参考客户端，代码不含开发者本机路径

| 环境变量 | 作用 |
| --- | --- |
| TLMNH_REFERENCE_PROBE | 本目录，供Gradle加入探针源码 |
| TLMNH_REFERENCE_HOME | 参考运行目录，与Gradle使用同一位置 |
| TLMNH_REFERENCE_UPSTREAM | 固定版本的上游checkout |
| TLMNH_REFERENCE_REPORTS | 可选的证据目录，默认在参考运行目录的evidence下 |
| TLMNH_REFERENCE_GIT | 可选的Git程序位置，默认使用PATH中的git |
| TLMNH_PORT_GRADLE | 可选的移植版Gradle程序，默认使用移植工程wrapper |

先在上游checkout对upstream-probe.patch执行git apply --check，通过后再应用
随后用上游wrapper加--init-script运行runClient，确保使用Java17
在本目录运行以下命令，A/A实验会重开已有参考世界；首次运行先通过control.py创建测试世界

```console
python control.py create_lab
python aa_experiment.py --keep-client
python fault_experiment.py
```

各脚本均支持--help；aa_experiment.py默认完成后正常退出客户端
组合执行时使用--keep-client，再由fault_experiment.py在完成后退出
compare_aa.py可单独比较两个已保存的受控样本，只判断原版重复性，不作跨版本等价判断

走动转换使用独立报告，参考客户端已启动时运行：

```console
python aa_experiment.py --scenario idle_walk_idle
```

该脚本默认正常退出参考客户端；切回移植版Java25构建环境后运行以下CPU重放：

```console
python ab_experiment.py --scenario idle_walk_idle
```

这是原地构造输入的动画转换合同，不是实际移动或行为AI测评；默认不加scenario时仍使用原待机报告

非零头转向使用同样步骤，将两条命令的scenario改为head_turn，新AA/AB报告独立保存

参考客户端正常退出后，将移植工程的构建环境切回Java25，在本目录运行python ab_experiment.py
它使用显式replay.init.gradle，将回放器临时加入test源码集，运行实际移植版CPU动画路径，不写入分发JAR
除两个正例外，还会在实际回放路径注入头部位移，并验证缺少输入字段时拒绝计算
每轮输出独立证据目录，保存实际输入哈希、加载类哈希、资源哈希与比较结果，ab-experiment.json指向最新结果

## 观测器协议

ReferenceObservationProbe在显式tlmnh.referenceProbe=true时读取游戏目录下tlmnh-reference/control/*.json
结果位于responses，采集数据位于captures；先写.tmp再改名为.json，每tick最多处理4条

| 请求 | 作用 |
| --- | --- |
| `{"command":"status"}` | 返回实际游戏版本、世界/玩家状态、界面及已加载模组清单 |
| `{"command":"create_lab"}` | 创建新的空气虚空世界，原生旁观模式；已有同名世界时拒绝覆盖 |
| `{"command":"open_lab"}` | 重开已经创建的参考世界 |
| `{"command":"clear_scene"}` | 请求清理带实验标记的女仆，另核对场景状态及maidCount |
| `{"command":"reload"}` | 场景清空后异步重载资源，完成后才允许受控采样 |
| `{"command":"spawn_case","model":"geckolib:winefox_hanfu"}` | 请求在该参考世界准备平台及指定原版女仆，返回UUID后再核对scene状态 |
| `{"command":"observe","entityUuid":"指定女仆UUID","frames":30}` | 采集该女仆接下来实际渲染的指定帧数，范围1至240 |
| `{"command":"sample_case","model":"geckolib:winefox_hanfu","frames":30,"seed":424242,"fault":"none"}` | 每次清场并重载后，用新实体从首次绘制开始受控采样 |
| `{"command":"shutdown"}` | 请求客户端正常退出 |

observe和sample_case先返回waiting-render，reload先返回waiting-reload，完成后才改为complete
60秒内未得到足够帧数则failed，客户端入口的单次等待另有上限
场景请求返回时ready仍为false，必须等待status中的scene为ready；失败会保留错误
测试女仆关闭行为AI并固定观察位置，只验证动画采集，不把这些场景当作行为AI测评
数据包含原版当前模型、骨骼变换和可见性，Gecko另有片段、控制器状态与时间偏移
Bedrock记录额外四元数和偏移，不能只以欧拉角作为完整姿态

当前格式为observation-v0；普通观测记录render-post，受控Gecko另存核心、头部和最终骨骼
allInputsCaptured和equivalenceVerified固定为false，不能把普通观测当作任意游戏轨迹的完整重放数据
受控模式另标记controlled-idle-v0，固定UUID、随机初始状态、tick、partial tick、落地与头部朝向
每次必须清理旧实体并重载资源，临时实体字段在绘制结束后恢复；采样步不等于现实播放帧时长
受控样本的inputs另标记controlled-empty-idle-v1，记录实际状态、查询值和绘制参数
只审查两个空手待机夹具，拒绝缺字段、未审查的活动片段依赖和额外动作层，不假定未知值为0
完整游戏轨迹、随机动作和其他状态仍未覆盖

资源核对按上游真实加载路径执行：唯一原版default pack的解包文件，以及常规资源管理器中的默认Gecko动画
多模型包时拒绝使用这个受限合同，防止把其他包的同名模型当原版基线
移植版资源必须与固定Git字节相同；原版有效JSON允许可复算的LF/CRLF换行变体，贴图等二进制必须逐字节一致
不忽略任意JSON内容变化，也不把资源相同当作贴图和UV已经正确绘制

采样只读当前动画结果，渲染阶段缓存在有界列表，文件输出在客户端tick完成
采集器本身可能影响帧时刻，后续实验必须测量其影响并验证可重放性

首个汉服样本的相邻seekTime间隔约0.16至0.30 tick，主片段是jump，不能把该场景假定为固定步长的idle
上游样本含28个控制器，其中magic_casting在这30帧中保持STOPPED；不能仅凭与移植版控制器数量不同就判动画错误
原版字段本身可读取，但必须补齐输入、初始状态和阶段对应关系，才能进入可靠对照

## 已完成的小样本验证

| 实验 | 实际结果 | 结论范围 |
| --- | --- | --- |

故障通过上游实际执行路径的测试钩子注入，未修改保存后的JSON来冒充端到端检出
上述结果只支持这两个有界用例中的机器对照，没有验证贴图、UV、GL状态或所有随机和物理组合
比较器使用原始精确数值，不按移植结果放宽容差；跨平台误差预算与四元数/矩阵归一化仍需另行校准
原版magic_casting缺于移植版时，只在每一步均STOPPED、无片段且时间参数未动的夹具中投影掉该层，否则不可判定
目前不批准扩大到全部模型批量验收

## 扩大测试前的门槛

1. 在一个Gecko酒狐和一个Bedrock选择中取得所需字段，任何模型回退或空骨骼都失败
2. 原版相同输入在独立重建实例后至少重复3次，解释重复误差和非确定性
3. 移植版完整消费相同轨迹，并验证随机输出、更新步长、暂停和状态清理
4. 人为注入位移、时序或动作选择错误，自动比较必须失败并定位首个分歧
5. 用实际渲染检查补数值姿态无法覆盖的贴图、UV和GL状态问题

未实现的首版必需动作不算跳过通过，采样不稳定标不可判定，不自动扩大容差或覆盖基线
这些门槛通过后再扩展全部酒狐与其余内置模型
基线更新按版本留存，不要求用户日常逐个模型观察画面，也不为每次push新增整套GPU Actions
