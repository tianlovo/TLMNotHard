# 原版游泳姿态与水面跳跃组件对照

本工具运行在固定的上游 TLM 提交 `8a3ac5e9eacf0c6d63adf8832949f3ce81484fe6`、Minecraft 1.20.1、Forge 47.2.0 与 Java 17 环境上。
采样仅在独立原版参考客户端的受保护展台中执行，不在 1.20.1 中加载移植版 JAR。

`reference.init.gradle` 复用已锁定的原版参考构建及只读类定义观察器，采集真实的 `MaidSwimManager`、`MaidSwimJumpTask`、原生 `Swim` / `Behavior` / `JumpControl` 与碰撞箱尺寸恢复结果。
姿态条件、流体高度、导航结束状态与随机输入均为受控输入；每个用例重建三个全新实体与任务实例，实体不挂载到自然运行的 Brain。

合同涵盖 32 种姿态条件、落地与夹层空间尺寸恢复以及六种跳跃生命周期，共计 120 行输入、312 个状态采样点。
原版姿态标志与实际 `Pose` 分开记录；现代眼高在尺寸刷新时更新缓存，睡眠眼高固定为 `0.2`。
体型放大后，按旧身体中心搜索最近的无碰撞中心点，因此在空气中恢复站姿可能改变脚底高度；找不到可用空间时保留原版放大后的碰撞箱，不自行编造延迟站立规则。

`SwimCoreReplayMain` 仅消费采集输入字段，驱动真实的移植版游泳管理器、跳跃任务及碰撞空间搜索算法。
`compare.py` 先核对原版选定类与构建身份、三份新建实例的 A/A 一致性，再比对移植版输出状态。
测试会在真实原版依赖处分别注入“忽略落地状态”和“允许水下跳跃”两类故障，要求比较器从实际状态差异检出异常，不能仅检查故障标签名称。
浮点数值容差设为 `0.000001`，任务状态、计时器与 RNG 调用次数仍要求严格一致。

本项检查不覆盖自然 Brain 调度、完整两栖导航、全量流体物理、完整忠实模式 F、增强模式 N 或 O/F/N benchmark。
移植版构建产物、源码提交与实际安装哈希由外层实验统一绑定，本工具不会仅凭组件级一致授予整版验收通过。
