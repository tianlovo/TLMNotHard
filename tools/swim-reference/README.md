# 原版游泳姿态与水面跳跃组件对照

使用固定 TLM `8a3ac5e9eacf0c6d63adf8832949f3ce81484fe6`、MC 1.20.1、Forge 47.2.0 和 Java 17
仅在独立原版参考客户端的受保护展台执行，不能在 1.20.1 加载移植 JAR

`reference.init.gradle` 复用已锁定的原版构建及只读类定义观察器
采集实际 MaidSwimManager、MaidSwimJumpTask、原生 Swim/Behavior/JumpControl 与尺寸恢复结果
姿态条件、流体高度、导航结束和随机输入受控；每次使用三个新实体/任务重建，实体不注册到自然 Brain

合同包含 32 种姿态条件、落地/夹层尺寸恢复和六种跳跃生命周期，共 120 行、312 个状态
原版姿态标志和实际 Pose 分开处理；现代眼高在尺寸刷新时缓存，睡眠眼高固定 0.2
增长后以旧身体中心搜索最近无碰撞中心，空气中恢复站立可能改变脚底高度
无法找到空间时保留原版增长后的碰撞箱，不另造延迟站立规则

`SwimCoreReplayMain` 只消费输入字段，执行实际移植管理器、跳跃任务及碰撞空间算法
`compare.py` 先核原版选定类和构建身份、三个新状态的 A/A，再比较移植状态
分别在实际原版依赖处注入忽略落地、允许水下跳跃，必须从结果差异检出，不能只看故障名称
数值容差为 0.000001，任务状态、计时和 RNG 次数仍须一致

这项检查不覆盖自然 Brain、完整两栖导航、全部流体物理、完整忠实 F、增强 N 或 O/F/N benchmark
移植产物、源码提交和实际安装哈希由外层实验绑定；工具不会据组件相等授予整版通过
