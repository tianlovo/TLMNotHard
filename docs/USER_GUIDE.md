# Indev 使用、配置与更新

简体中文 | [English](USER_GUIDE.en.md)

本说明适用于 GTNH 2.9.0 的 TLMNotHard 开发候选，尚无正式发布版
已实现功能、各候选实测范围和未通过项以仓库 `PROGRESS.md` 为准
包内 `audit-report.json` 用于资源和结构检查，游戏验收及配音发布事项另行记录

## 安装与更新

使用完整的 GTNH 2.9.0 客户端和独立服务端，两端安装字节相同的 TLM JAR
游戏运行环境为 Java 25；模组字节码目标仍为 Java 8
本模组需要 GTNH 2.9.0 整包提供的 API

1. 正常退出两端，确认服务端保存并停止
2. 备份服务端完整世界目录、两端配置、原 TLM JAR 和原更新记录
3. 将对应端的 ZIP 解压到目标实例外，核对 `SHA256SUMS.txt` 与候选 JAR SHA
4. 安装 Python 3，再用 `python -m pip install rich` 安装 Rich
5. 在解压目录运行 `python update.py`，沿菜单选择对应的客户端或服务端真实目录
6. 两端更新完成、JAR 摘要相同后，再启动服务端和客户端

客户端目标含 `mmc-pack.json`，也可选择其下 `.minecraft`；服务端目标含 `lwjgl3ify-forgePatches.jar`
工具只管理 TLM JAR 和 `.tlmnh-distribution/<端别>` 资料，不修改整包配置及 `.gtnh-managed-*.json`
它只替换登记过名字及精确 SHA 的旧 JAR，或已有 TLM 托管记录中的确切版本
遇到未知旧包、同名不同字节或用户改写会拒绝，保留现场供核对

更新器会核对可识别的所选实例进程记录；其他启动器仍须人工正常退出
检查 `session.lock` 不能证明 1.7 多人客户端或服务端已经停止
重复安装相同包会保持现有文件；备份和回滚记录保存在 `.tlmnh-update-backups/<端别>`
使用更新菜单的前提及详细范围见 ZIP 根目录 `README.md`

## 获取和基本操作

当前进度从可重复使用的空魂符框开始，在合金炉中消耗 GT 烤蛋糕充制女仆核心
该核心路线可在蒸汽阶段进行；神龛使用 LV 装配机
具体材料以当前候选注册的 NEI 配方为准，成本和机器时长仍是 Indev 平衡值

在合适方块顶面使用核心，凭证先绑定使用者，再尝试释放女仆
位置受阻时保留已绑定魂符供原主人重试；复制凭证不会增加兑现次数
成功后返回空魂符框，下次充制仍消耗材料
可配置的首次赠送和野生生成是独立途径，当前新配置默认均关闭
开启野生生成后，可用蛋糕驯服未绑定女仆；首版不提供换主人功能

- 主人主手右键打开女仆页面，设置任务、日程、家园、装备、模型和配音
- 空手潜行右键切换坐下；女仆骑乘或载有乘客时先放下，再次操作才切换坐姿；鞍右键背起或放下女仆
- 未命名的命名牌打开命名页；已有名称的命名牌沿原生命名交互
- 潜行使用金苹果、可饮用药水或牛奶进行照料；原材料与容器沿实际物品规则处理
- 用空玻璃瓶提取经验，每瓶消耗 12 点女仆经验；潜行可批量提取
- 配音页选择此女仆的音包或本机试听；全局设置页调整本机声音、气泡和图标缓存偏好

女仆页的信息图标显示实际名称和饱食度属性；饱食度默认 20，沿原版本体规则，不自行消耗该属性

女仆页写操作受主人、距离、当前窗口和实际权限检查，旁观模式不能修改女仆
护甲、主副手、背部物品和普通背包使用各自槽位；模型自带附件的显示与遮挡仍有区别
任务页切换攻击或弓兵时，若主手已适用则保留；否则从六格背包中按槽位顺序选择首件合适武器
该武器与原主手整栈交换，保留耐久和完整 NBT；背包没有合适武器时仍可切换任务，手中物品保持
在当前 GTNH 配置下，关窗优先把光标物品放回玩家库存；满包时可能产生真实掉落
关闭后可从玩家库存和地面掉落确认物品去向

死亡胶片沿墓碑领取流程获得，放入神龛后按页面提示复活
复活消耗主人生命，操作前应确认自身状态和周围空间
胶片、物品保管、经验及复活凭证分别记录，不能用复制品获得额外库存或复活权

## 配置入口

服务端在首次正常启动时生成 `config/tlmnh.cfg`；修改启动配置后重启服务端
已有显式值会保留，更新 JAR 不会自动替换旧配置

| 配置 | 当前 Indev 默认值 | 作用 |
| --- | --- | --- |
| `acquisition.B:naturalSpawning` | `false` | 野生生成开关 |
| `acquisition.B:giveInitialSlab` | `false` | 每玩家一次的绑定魂符赠送；满包等待空位 |
| `acquisition.I:naturalWeight` | `1` | 生成权重，范围 1～100，每组一只 |
| `acquisition.I:naturalBiomes` | `1, 4` | 允许生成的群系数字 ID 列表 |
| `acquisition.I:naturalDimensions` | `0` | 允许生成的维度数字 ID 列表 |
| `behavior.S:profile` | `enhanced` | 服务端启动策略，可选 `legacy_prototype` 或 `enhanced` |
| `combat.I:ownerCombatAcquireRange` | `20` | Enhanced 非家园目标获取半径，以主人为中心，范围8～24格 |
| `combat.I:ownerCombatRetainRange` | `24` | 当前有效战斗会话的同一目标保持半径，以主人为中心，范围8～24格 |

获取半径大于保持半径时，服务端会把获取值降至保持值，写回配置并记录警告
取消战斗后，原目标需要重新满足获取条件
女仆自身及战斗移动目的地受主人16格活动域约束，目标距女仆最多24格，家园采用其WORK活动域
装备、受击线索、周期侦察和当前目标共同决定有效检测范围，实际发现仍取决于视线、已加载区块扫描和预算

Forge 文件按分类和类型前缀保存键，下例选择增强策略

```text
behavior {
    S:profile=enhanced
}
```

策略作用于按该服务端配置加载的已有及新女仆，不把策略选择写成每女仆迁移字段
未知值或开发专用值会保留原配置并告警，回到当前旧策略；研究组件不是正式配置选项
新配置或缺少该键时默认使用 Enhanced，已有显式 `legacy_prototype` 值继续使用 Legacy；首发默认已选 Enhanced
其他家园、声音、进食、感知、导航和战斗键见生成文件的说明，避免用旧版本表格覆盖它们

本机 `config/tlmnh-client.cfg` 的全局页只保存以下偏好，不更改服务端女仆任务

| 配置 | 当前默认值 |
| --- | --- |
| `sound.I:GlobalMaidSoundFrequency` | `100`，范围 0～100 |
| `render.B:GlobalMaidShowChatBubble` | `true` |
| `model.B:EnableModelIconCache` | `false` |

单只女仆的音包、声音频率和任务由女仆页面单独设置；本机全局页保存或取消只影响本地偏好

## 存档回滚与故障保全

更新菜单的回滚只恢复 TLM JAR、资料和对应托管记录，不恢复游戏世界
若新版已保存存档，降级时先正常停两端，再恢复升级前配对的旧 JAR、完整世界和配置
完整世界包括所有维度、`playerdata`、实体区块及 `data` 账本；不能只恢复一个玩家文件
同时保留新版世界的独立副本，不能用修改 schema 数字代替迁移

出现诊断提示时，保留候选版本、两端 JAR SHA、诊断编号、日志及原存档备份
本模组会保留无法确认的原始物品 NBT，并停用相应能力；请保留库存和兼容基线供核查
客户端基线为 `config/tlmnh-client-compatibility.dat`，服务端兼容记录位于世界数据目录
恢复已审核的兼容环境后，可右键保护包尝试拆包；附近的主人也可使用下列命令

```text
/tlmnhprotect recover <女仆实体数字ID>
```

该命令逐件取回可用保管物品，满包或仍不兼容时保留原数据，不提供忽略摘要的强制恢复
零食柜的自有保管项可沿潜行交互取回

## 内容与发布边界

候选资源保留 435 个配音、10 个基础音效、332 个补充原资源，以及 254 项内置模型目录
酒狐包含 21 个基础条目和 14 个额外纹理；命名彩蛋仍按原门控制，不通过普通占位项选择
保留资源文件不表示启用其全部原玩法，资源完整性也不表示所有成像和跨模块场景已验收

首版不含外部模型导入、YSM 联动、LLM、换主人及空闲和战斗以外的工作
