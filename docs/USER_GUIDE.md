# 0.1.0 使用、配置与更新

简体中文 | [English](USER_GUIDE.en.md)

本说明介绍 `0.1.0` 的玩法与更新步骤。正式版当前处于发布准备阶段，公开下载仍为 `0.1.0-beta.2`。
当前实测、保留失败与最终发布记录见仓库 [开发进度](../PROGRESS.md)。

## 安装与更新

使用完整的 GTNH 2.9.0 客户端与独立服务端，游戏运行环境为 Java 25，模组字节码目标为 Java 8。

1. 从同一 GitHub Release 下载目标版本主包，并按该页 `SHA256SUMS.txt` 核验。
2. 正常停止客户端与服务端，确认存档保存完成。
3. 备份完整世界、两端 `config/`、原 JAR 及更新记录。
4. 将字节相同的新主包放入两端 `mods/`，移出旧 TLM JAR，避免同时加载两个版本。
5. 核对两端摘要后启动。普通游玩使用主包，`tlmnhdevtools` 为独立开发附属模组。

本地验证增量包的 `update.py`、Rich 菜单、备份与回滚说明见 [打包文档](../scripts/distribution/README.md)。
该工具只管理已登记的 TLM 文件，遇到未知 JAR 或同名异字节文件会保留现场并拒绝覆盖。

## 获取和基本操作

当前进度从可重复使用的空魂符框起步，在合金炉中消耗 GT 烤蛋糕即可充制女仆核心。
核心路线可在蒸汽阶段完成，神龛则需使用 LV 装配机合成。
材料、机器耗时和能耗以当前版本的 NEI 配方为准。

在合适方块的顶面使用核心时，凭证会先绑定使用者，再尝试释放女仆。
若目标位置受阻，会保留已绑定魂符供原主人重试；复制凭证不会增加可兑现次数。
成功释放后会返还空魂符框，下次充制仍需消耗材料。
可配置的首次赠送与野生自然生成属于独立获取途径，在新配置中默认均关闭。
开启野生生成后，可用蛋糕驯服未绑定女仆；首版不提供更换主人功能。

- 主人主手右键打开女仆页面，配置任务、日程、家园范围、装备、模型与配音。
- 空手潜行右键切换坐下状态；女仆处于骑乘或载有乘客时会先解除骑乘，再次操作才切换坐姿；手持鞍右键可背起或放下女仆。
- 未命名的命名牌可打开命名页，已有名称的命名牌沿用原生命名交互。
- 潜行使用金苹果、可饮用药水或牛奶进行照料，物品消耗与容器返还遵循实际物品规则。
- 手持空玻璃瓶可提取女仆经验，每瓶消耗 12 点经验，潜行时支持批量提取。
- 配音页可选择当前女仆的音包并在本机试听；全局设置页用于调整本机音量频率、聊天气泡与图标缓存偏好。

女仆页的信息图标显示实际名称与饱食度。饥饿与进食规则见下文。

女仆页的写操作受主人身份、距离、当前窗口与实际权限检查保护，旁观模式无法修改女仆状态。
护甲、主副手与普通背包使用各自独立的槽位，不同内置模型自带附件的显示与遮挡表现有所差异。
在任务页切换近战或弓兵任务时，若当前主手武器已适用则直接保留；否则按槽位顺序从 36 格背包中选取第一件适用武器，与当前主手整栈交换并保留耐久与完整 NBT。若背包中无适用武器，任务仍会正常切换，主手物品保持原位。
在当前 GTNH 配置下，关闭窗口时会优先将光标持有的物品放回玩家背包，背包已满时可能产生真实地面掉落。关闭窗口后请结合玩家库存与地面掉落确认物品去向。

死亡胶片通过墓碑领取流程获得，放入神龛后按界面提示执行复活。
复活会消耗主人生命值，操作前请确认自身血量与周围可用空间。
胶片、保管库存、经验与复活凭证分别独立记录，复制物品无法获取额外库存或复活次数。

## 背包、饰品与携带容器

女仆背包默认开放全部 36 格，主手、副手和护甲使用独立槽位。背部物品按既有显示规则展示。饰品页共有 30 格：

| 好感等级 | 好感点数起点 | 可用饰品格 |
| --- | --- | --- |
| 0 | 0 | 10 |
| 1 | 64 | 10 |
| 2 | 192 | 20 |
| 3 | 384 | 30 |

好感下降后，锁定行中的物品仍保存在存档内，锁定行的装备能力停用。
可用饰品包括本模组两种铃铛及适配的飞行、氧气和隔热装备。将装备放进普通物品栏仅表示携带，装备效果按实际穿戴槽判定。

拾取和库存转移优先尝试携带背包的内部容器，再合并女仆背包与双手。
支持 Eydamos Backpack、Adventure Backpack、Forestry Backpack、Extra Utilities Golden Bag 和 ProjectRed 背包。
各背包继续遵守提供方的物品准入、容量和锁定模式；Golden Bag 在 GTNH 默认配置中关闭，需整包配置允许后才有对应物品。
Forestry 锁定模式中的物品可保留，但不能自动存入或取出。先解锁，再让女仆取用育种物资。

## 两种铃铛和维护工作

铃铛通过饰品栏穿戴。选定工作任务并使用工作日程后，女仆在已加载区块内工作。

| 项目 | 维护铃铛 | 育种铃铛 |
| --- | --- | --- |
| 绑定 | 手持并潜行右键地面，切换当前区块的绑定 | 手持并潜行右键田块中心土壤，绑定同层 3×3 地块；点击作物架会换算到其下土壤 |
| 上限 | 同一维度最多 16 个区块，可不相邻；每轴最大区块坐标减最小坐标不超过 8 | 同一维度的一块 3×3 田 |
| 解绑 | 再次点击已绑区块；最后一个解绑后恢复未绑定状态 | 再次点击同一中心位置 |
| 清空 | 将铃铛单独放入合成栏，按已注册的清空配方取出 | 同左 |

清空配方只清除绑定数据，保留物品的其他 NBT。维护铃铛不能直接混绑其他维度。
穿戴铃铛后，主人在女仆 8 格内潜行并查看女仆，可预览其绑定范围；离开范围、解除潜行或取下/锁定铃铛后预览关闭。

维护任务扫描绑定且已加载区块中的普通 GregTech 维护仓，修复其真实六项维护状态并巡回检查。
将有效 GT 扳手放在副手，维修时会靠近到 3.5 格以内。
自动维护仓不属于这个任务的目标。维护操作不消耗扳手、材料、耐久或电量。
铃铛不提供区块强加载；跨区块巡检需要原本可通行、已加载的路线。

## CropsNH 世界育种

1. 准备中心土壤及周围八格，保证上方可用。农田使用真实水源灌溉，石质作物按提供方要求使用土壤和下垫。
2. 绑定育种铃铛，放入已开放的饰品槽，在女仆任务页选择育种并打开育种配置页。
3. 选择单个可在世界中种植的目标作物，或选择变异池。设置 Ga（产量）、Gr（生长）、Re（抗性）及 OR/AND 逻辑；满 31 模式要求三项全部达到 31。
4. 提供真实母本种子或 CropsNH 接受的替代果实、CropsNH 铲子、作物架，以及所需土壤、下垫和合格采矿工具。
5. 保持工作日程与可达空间。女仆在距田块中心 4 格内操作，按自然生长节奏补植、除草、杂交、收种并替换较弱母本。

OR 表示任一设置属性达标即可，AND 要求三项都达标。
普通布局使用五个母本单架和四个双架，完整铺设需要 13 根作物架；四亲本配方使用四个母本和中心双架。
杂交会按 CropsNH 规则消耗双架中的第二根，请持续准备作物架。

育种取用支持裸槽和可取用的携带背包，借出的工具在使用及磨损后归还。
掉落子代优先入携带背包，也能再取出作为新母本。日常工作餐会保留可作育种输入的种子和替代果实，紧急回血与呼吸恢复仍按各自规则处理。
更换石质土壤或下垫会检查真实工具类别和挖掘等级，执行真实磨损并回收方块；高等级扳手不能替代合格采矿工具。

并非每个 NEI 条目都能在世界中育种。机器专用作物或当前缺少可行亲本的目标会给出提示。
缺铃铛、绑定、维度、田块、目标、铲子、母本、作物架、土壤、下垫或挖掘工具时，在线主人会收到带女仆名字的聊天提醒。
相同缺件集合每 1200 tick 才重发，缺件变化会立即更新。生产循环按自然生长运行，不包含测试加速。

## 饥饿、热物品与生存装备

饱食度上限为 20，移动、游泳、跳跃和有效战斗等动作产生耗竭，先消耗饱和度，再消耗食物值。
真实进食会扣除食物并结算营养及容器返还，也可从可用携带背包取食。自然回血和饥饿伤害遵守当前游戏规则、难度及整包饥饿适配。
只在背包中保留育种果实可能缺少可吃的日常食物，出发前另备食物。

Extra Utilities 治愈之斧放在副手时，每 40 tick 补 1 点食物值和相应饱和度。
主手攻击按原提供方语义处理亡灵伤害、僵尸村民转化及耗竭，其他生物不会因此受到普通斧击或治疗，武器不损失耐久。

热物品检查覆盖全部 36 格裸槽和双手，携带背包内部的物品免于该项灼伤扫描。
真实受热伤累计后会丢弃裸露热物品，并进入 200 tick 防误捡期；仍能安全收进背包的部分可继续拾取。
完整防热装备可按提供方规则免伤。GT++ 热锭的变为普通锭依赖实际冷却配方，本模组不会替它增加库存自动冷却。

### 飞行与护甲

| 装备组 | 穿戴和能力 |
| --- | --- |
| Adventure Backpack | 直升机背包或煤炭喷气包，胸部或已开放的适用饰品槽；直升机背包在水中停用飞行能力 |
| IC2 | 燃油/电力喷气包，或带真实内置喷气标签的量子胸甲；独立喷气包可放适用饰品槽 |
| GraviSuite 进阶装备 | 进阶喷气包、进阶纳米胸甲，按真实胸甲/独立喷气包类型穿戴 |
| GraviSuite 重力胸甲 | 胸甲槽，提供对应悬浮与飞行能力 |

飞行装备支持跟随空中的主人、悬浮与有碰撞的三维移动，飞行推进本身不扣 EU 或燃料。
护甲防御、供氧和特殊效果独立结算，会按实际提供方消耗电量或氧气。
纳米/量子护甲保留真实防御和消耗；适用头盔的水下补气、异常状态清除、罐头取食与空罐返还、夜视亮光惩罚，
胸甲及完整防化服的灭火等能力按装备和资源条件生效。

### 太空与坠落自救

氧气面罩、供氧装具、氧气罐和适用隔热内衬放在已开放的饰品槽。
非可呼吸环境需要有效供氧组合并实际扣氧，无限氧气罐与可呼吸区域按提供方机制处理。
隔热按四个部位的实际内衬强度与环境结算，支持 GalaxySpace 二阶内衬。物品放在锁定行不会提供保护。

坠落自救会优先检查已有保护、可用水源和装备，再在适用环境尝试真实落地水或救援船。
需要真实可用的水桶或受支持的船、可落点及主人权限；放置事件被取消时保留物品。
船回收核对实际实体和状态。自救能力受环境与提供方规则约束，进入太空或高空前仍应备齐对应装备。

## 配置入口

服务端在首次正常启动时生成 `config/tlmnh.cfg`，修改启动配置后需重启服务端生效。
已有显式配置值会继续保留，更新 JAR 不会自动覆盖旧配置文件。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `acquisition.B:naturalSpawning` | `false` | 野生生成开关 |
| `acquisition.B:giveInitialSlab` | `false` | 每名玩家一次的绑定魂符赠送；满包时等待空位 |
| `acquisition.I:naturalWeight` | `1` | 生成权重，范围 1～100，每组一只 |
| `acquisition.I:naturalBiomes` | `1, 4` | 允许生成的群系数字 ID 列表 |
| `acquisition.I:naturalDimensions` | `0` | 允许生成的维度数字 ID 列表 |
| `behavior.S:profile` | `enhanced` | 服务端启动策略，可选 `legacy_prototype` 或 `enhanced` |
| `combat.I:ownerCombatAcquireRange` | `20` | Enhanced 非家园目标获取半径，以主人为中心，范围 8～24 格 |
| `combat.I:ownerCombatRetainRange` | `24` | 当前有效战斗会话的同一目标保持半径，以主人为中心，范围 8～24 格 |

当获取半径大于保持半径时，服务端会将获取半径下调至保持半径，写回配置文件并输出警告日志。
战斗取消后，原目标需重新满足获取条件才会再次进入战斗。
女仆自身及战斗移动目的地受主人 16 格活动域约束，目标与女仆距离不超过 24 格，家园模式则采用对应的 WORK 活动域。
装备、受击线索、周期侦察与当前目标共同决定有效检测范围，实际发现仍取决于视线、已加载区块扫描及运算预算。

Forge 配置文件按分类与类型前缀保存键值，下例用于启用增强行为策略：

```text
behavior {
    S:profile=enhanced
}
```

该策略作用于当前服务端配置下加载的存量与新建女仆，不作为单只女仆的存档迁移字段。
遇到未知值或仅限开发使用的配置值时，服务端会保留原配置文件、记录告警并回退至当前旧策略；研究用组件不属于正式配置选项。
新建配置或缺失该键时默认启用 Enhanced，已有显式 `legacy_prototype` 配置继续使用 Legacy；首版默认策略定为 Enhanced。
家园、声音、进食、感知、导航与战斗的其余配置键请参考生成文件中的注释说明，避免用旧版本表格覆盖现行配置。

客户端本地的 `config/tlmnh-client.cfg` 全局页仅保存以下本机偏好，不会改动服务端女仆任务：

| 配置 | 当前默认值 |
| --- | --- |
| `sound.I:GlobalMaidSoundFrequency` | `100`，范围 0～100 |
| `render.B:GlobalMaidShowChatBubble` | `true` |
| `model.B:EnableModelIconCache` | `false` |

单只女仆的音包、语音频率与任务在各自的女仆页面单独配置；本机全局页的保存或取消仅影响本地显示与音效偏好。

## 存档回滚与故障保全

更新菜单中的回滚仅恢复 TLM JAR、配套资料及对应托管记录，不会回滚游戏世界存档。
若新版本已保存过世界，降级时须先正常停止客户端与服务端，再一并恢复升级前配对的旧双端 JAR、完整世界目录与配置文件。
完整世界包含全部维度、`playerdata`、实体区块及 `data` 账本，不能仅恢复单个玩家存档文件。
降级前请同时保留新版世界的独立备份，切勿通过手工修改 schema 编号代替数据迁移。

出现诊断提示时，请保留候选版本号、两端 JAR SHA、诊断编号、运行日志及原始存档备份。
遇到无法确认兼容性的物品时，本模组会封存原始物品 NBT 并停用受影响的能力；请保留当前库存与兼容基线文件以便排查。
客户端兼容基线位于 `config/tlmnh-client-compatibility.dat`，服务端兼容记录保存在世界数据目录中。
恢复经审核的兼容运行环境后，可右键保护包尝试拆包，附近的主人也可执行以下命令：

```text
/tlmnhprotect recover <女仆实体数字ID>
```

该命令会逐件取回可用的保管物品；若背包已满或兼容问题尚未解除，会继续保留原始封存数据，不提供跳过摘要校验的强制恢复。
零食柜中的自有保管物品可通过潜行交互取回。
