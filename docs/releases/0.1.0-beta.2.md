# 0.1.0-beta.2

TLMNotHard 第二个公开 Beta，面向 GTNH 2.9.0、Minecraft 1.7.10、Forge 10.13.4.1614（Java 25 运行时）。
本版聚焦工程源码分层、第三方适配解耦、公开扩展契约自包含与开发工具拆包，外部存档 Schema、网络包编号、注册名与配置键与 `0.1.0-beta.1` 完全兼容。

## 本次内容

- **开发诊断工具独立拆包**：原混入生产包的 `/tlmnhdev` 命令、客户端自动化控制、GPU 渲染探针、测试夹具与基准回放全部迁入 `src/devtools`、
  `src/devtoolsTest` 与 `src/replay`，单独构建为 `tlmnhdevtools` 附属模组，发布主包不再携带任何开发期类。
- **客户端与纯内核模块物理隔离**：纯 Java 数学表达式解析器拆为独立 Gradle 子工程 `:kernel:molang`；313 个客户端渲染、GUI、模型与动画类迁入
  `src/client/java` 与 `src/clientTest/java`，在编译期根除公共服务端代码误引客户端类型的风险。
- **第三方可选模组适配治理**：16 个外部模组的公共与客户端适配代码迁入独立的 `src/compat` 与 `src/compatClient` 源集，经 `CompatServices`
  与 `ClientCompatServices` 在启动期通过 `ServiceLoader` 一次性绑定并冻结领域 SPI；核心业务不再直接依赖可选模组编译期 API 或散落反射。
- **公开扩展 API 自包含与构建门禁**：`com.tianluoqaq.tlmnh.api.behavior` 移除全部 `common.*` 内部实现耦合，补齐纯值类型 `MaidBehaviorGroup`
  与手部租约/观测契约；构建约定与归档审查收敛至 `build-logic` 预编译插件，并新增 `verifyArchitectureBoundaries` 静态门禁守护源集依赖方向与开发开关单点读取。
- **既有玩法与内置资产完整保留**：女仆核心交互、双手与六格背包、254 个内置模型选择、435 个配音与 10 个基础音效、神龛与魂符、女仆床、最小零食柜、
  GTNH 阶段配方以及 Enhanced 统一战斗与行为会话能力均与 `0.1.0-beta.1` 保持一致。

## 安装与升级

1. 从本页 Assets 下载 `tlmnh-0.1.0-beta.2.jar`（普通游玩无需下载或安装开发专用 `tlmnhdevtools`），对照 `SHA256SUMS.txt` 校验 SHA-256。
2. 正常停止客户端和服务端，完整备份世界存档、两端 `config/` 与旧版 `tlmnh-0.1.0-beta.1.jar`（或更早 TLM JAR）。
3. 将同一份 `tlmnh-0.1.0-beta.2.jar` 放入客户端与服务端的 `mods/`，将旧版 JAR 移出 `mods/`，再启动两端。

本版可直接读取 `0.1.0-beta.1` 存档与配置文件；新配置默认启用 `enhanced` 策略，已有显式 `legacy_prototype` 配置继续生效。
操作按键、服务端配置项与双端成对回滚步骤详见仓库 `docs/USER_GUIDE.md` 与 `docs/USER_GUIDE.en.md`。

## 已知问题与后续范围

- `LEGACY-GROUND-001` 待处理：Legacy 原型地面跟随用例在第 14 tick 触发位移平方小于 1 的既有守卫，本轮重构未改动 Legacy 决策算法，留待稳定版前专项修复。
- `COMBAT-STATS-001` 待处理：共有战斗统计工具协议与正式 seed/顺序采集绑定待补，统计比较结论尚未签署。
- 新增生存与装备适配（落水/坠落自救、太空供氧、纳米/量子护甲支持、背包内部容器免热锭灼烧）、真实饥饿机制与治愈之斧副手恢复/攻击适配将在后续版本实现。
- 带复杂 NBT 物品的真实客户端 Shift 转移，以及 `0.1.0` 正式稳定版发布前的跨模块组合、双端联机与玩家实机终验仍待完成。
